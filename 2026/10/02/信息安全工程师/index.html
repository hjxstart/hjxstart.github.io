概念

第1章 网络信息安全概述 3-1

1. 网络空间: 它是国家继陆、海、空、天四个疆域之后的 "第五疆域"。
2. 网络信息安全基本属性: "机密性"(对应涉密), "完整性"(对应篡改), "可用性"(对应破坏), 抗抵赖性, 可控性
3. "防御、监测、应急、恢复（口诀: 房间积灰），被称为网络安全保障的“四大支柱”"
4. 网络安全管理方法主要有：风险管理、等级保护、纵深防御、层次化保护、应急响应以及PDCA (Plan-Do-Check-Act)方法等。
5. 信息安全相关法律: 网络安全法(2017/06/01), '网络安全法修订版(2026/01/01)', 密码法(2020/01/01), 数据安全法、关基条例(2021/09/01), 个人信息保护法(2021/11/01), 网络安全审查办法(2022/02/15)
6. 网络安全登记保护制度的核心工作流程: 定级 -> 备案 -> 建设整改 -> 等级测评 -> 运营维护(监督检查)
7. 国家对密码实行分类管理，分为三大类: "核心密码、普通密码和商用密码"。
8. 互联网域名安全管理: 域名系统出现网络于信息安全事件时, "应在24小时内向电信管理机构报告"。
9. 国家计算机网络应急技术处理协调中心 (简称"国家互联网应急中心，英文缩写为CNCERT或者CNCERT/CC")

第2章 网络攻击原理与常用技术 7

1. 网络攻击概念中常见的危害行为主要分为四类: 信息泄露攻击、完整性破坏攻击、拒绝服务攻击(Dos)、非法使用攻击。
2. 网络攻击模型 "常考": 攻击树模型、MITRE ATT && CK模型(真实数据抽象形式,CVE漏洞)、网络杀伤链(Kill Chain)模型(分七个模型)
# 网络攻击常见技术
1. 十种端口扫描: TCP标志位(FLAGS解析)包含 "SYN(建立连接), FIN(关闭连接), ACK(确认响应), PSH(推送数传输), RST(重置连接), URG(紧急数据)"。几种端口扫描技术（完全连接扫描['完整连接'有日志]，半连接扫描['只完成前两次握手']，SYN扫描['当目标主机返回响应后，立即切断连接过程，并查看响应情况',有RST]，ID头信息扫描['这种扫描方式需要用一台第三方机器配合扫描，并且这台机器的网络通信录非常少，即dumb主机']，隐蔽扫描[代理]，SYN/ACK扫描[返回RST说明端口关闭，没有返回就是开放]，FIN扫描[返回RST说明端口关闭，没有返回就是开放]，ACK扫描，NULL扫描[全部标志位'全部置空'发送，返回RST说明端口关闭，没有返回就是开放]，XMAS扫描[全部标志位'全部置1'发送，返回RST说明端口关闭，没有返回就是开放]） 。
2. 拒绝服务: 常见类型 "同步包风暴(SYN Flood), UDP洪水(UDP Flood), Smurf攻击(隔山打牛,让其他机器回复目标), 垃圾邮件, 消耗CPU和内存资源的攻击, 死亡之Ping(Ping of Death,大于64k的包), 泪滴攻击(Teardrop Attack,分包让目标无法组包完成), 分布式拒绝服务(DDos,很多肉鸡同时攻击)"。
3. 恶意代码: 类型有计算机病毒、'网络蠕虫(1988年由小莫里斯编制，感染UNIX主机。典型代码[红色代码；震网])'、特洛伊木马、后面、逻辑炸弹、僵尸网络等。
# 黑客常用工具
主要包括: 扫描器、远程监控、密码破解、网络嗅探器、安全渗透工具箱等。
1. 扫描器分为三类: '地址扫描器、端口扫描器、漏洞扫描器'
2. 经典扫描软件介绍： Nmap, Nessus, SuperScan
3. 远程监控:(代理软件) 冰河、网络精灵、Netcat.
4. 密码破解: 常见的破解方式有 口令猜测、穷举搜索、撞库。常用工具有: John the Ripper(Linux,审计系统密码), LOphtCrack(LC5, Windows)
5. 网络嗅探器(抓包): 常用的工具有 Icpdump, DSniff, 'WireShark'等
6. 安全渗透工具箱: Metasploit, Back Track5(BT5)

第3章 密码学基本理论 5-4

## 1. 密码学概况 【有时考】
1. 密码学主要由 '密码编码' 和 '密码分析' 两个部分组成。
2. 1949年，'香农' 发布了著名的论文《保密系统的通信理论》，增加了 '混乱(Confusion)' 和 '扩散(Diffusion)'的密码技术新技术。奠定了现代密码学的理论基础。
3. 20世纪70年代，RSA（公钥密码学）及Diffie-Hellman算法的发明者均获得了计算机领域的 '图灵奖'。
4. 我国密码发展里程碑：2005年《电子签名法》施行；2006年公布国产密码算法；'2020年1月1日《中华人民共和国密码法》正式实行'。
5. 密码学基本概念: M(Message消息,明文), K(Key密钥), E(Encryption加密), D(Decryption解密), C(Ciphertext密文)

## 2. 密码体制分类 【常考】
1. 根据密钥特点，密钥体制分为 '私钥' 和 '公钥' 密码体制两种，而介于两者之间的称为 '混合密码体制'。
# 私钥密码体制(对称密码体制)
1. 核心特点: '加密和解密使用相同的密钥'
2. 密钥分配与管理: 密钥的安全性至关重要。在网络环境中，若有n个用户两两通信，则需要维护 'n(n-1)/2个密钥'。
3. 优缺点总结: 优势(处理速度快)， 缺点(存在三大难题--密钥分配困难、密钥管理复杂、以及无法认证信息来源[不可否认性差])
4. 典型算法代表: 'DES/3DES/AES/RC4/RC5/IDEA/SM1/SM4'
# 公钥密码体制(非对称密码体制)
1. 主要技术优点: 密钥分发方便、密钥保管量少、功能扩展强(天然支持数字签名，可用于身份认证和完整性校验)
2. 典型代表算法: 'RSA算法、椭圆曲线密码(ECC)、SM2国密算法'等。
# 混合密码体制
混合密码体制利用公钥密码体制分配私钥密码体制的密钥，消息的收发双方共用这个密钥，然后按照私钥密码体制的方式，进行加密和解密运算

## 3. 常用密码算法 【必考】
# 对称加密算法-DES【重点】
1. DES算法：是一个 '分组加密算法', 密钥长为64位，但实际有效长度位'56比特'。数据8个字节，密钥8个字节，模式有加密/解密模式。
2. '分组加密(块加密)': 将数据分为固定长度的组，按组进行计算，如DES、AES、RC5等。
3. '序列加密(流加密)': 对数据按位或字节逐个进行加密处理。如RC4, ZUC等。
4. 3DES算法: '3DES并非加密三次，而是 "加密-解密-加密"， 其有效密钥长度为112为'
5. IDEA算法: 明文和密文分组均为64比特，"密钥长度为128比特"
6. AES算法: 支持的密钥长度至少为 '128、192和256比特'。
# 非对称加密算法-RSA 【重点】
1. RSA算法概述：'公钥和私钥都可用于加密消息', 用于加密的密钥与解密的密钥不同。它能有效保障数据传输的机密性、完整性、真实性和不可否认性。
2. 核心数学基础：理解RSA概念掌握以下概念：因素、素数、余数、模运算、逆元、欧拉函数、欧几里得算法（辗转求余）。
3. RSA密钥生成步骤（基于大整数因子分解困难性）
	1. 生成素数: 随机选择两个足够大得素数 p 和 q
	2. 计算模数: 计算这两个素数的乘积 n = p * q, n 的长度即为密钥的长度(如2048位)
	3. 计算欧拉函数: 计算小于n且与n互素的整数个数，即欧拉函数 x(n) = (p-1)(q-1)
	4. 选择公钥指数: 选取随机数e，满足 1 < e < x(n)，且 e 与 x(n) 互素 (gcd(e,x(1))=1)，通常e取65537
	5. 计算私钥指数: 计算 d ，使得 d == e-1(modx(n))，即d是e在模x(n)下的乘法逆元。
	6. 密钥分配: '保密d、p和q（私钥核心），公开n和e(公钥)'。
# 国产密码算法概览【考试常考重点】
我国已经发布的国产密码算法主要包括: "SM1分组密钥算法、SM2椭圆曲线公钥密码算法、SM3密码杂凑算法、SM4分组密码算法、SM9标识密码算法"。
1. SM1 分组密码算法：算法未公开，属于国家秘密。通常以硬件形式集成在芯片中，用于金融、政务等关键领域的加密保护。
2. SM2 椭圆曲线公钥密码算法: 基于椭圆曲线密码体制。由于 1024 位RSA算法安全性面临挑战，我国正式采用SM2算法作为替代，用于数字签名和密钥交换。
3. SM3 密码杂凑(哈希)算法: 主要用于数字签名及验证、消息认证码生成及验证、随机数生成等，是保障数据完整性的核心算法。
4. SM4 分组密码算法: 无线局域网标准的分组加密算法，属于对称密码算法，其安全强度和运算性能与国际标准AES算法相当。
5. SM9 标识密码算法: 主要用于身份认证。其加密强度等同于3072位密钥的RSA加密算法，适用于大规模、分布式的身份鉴别场景。

## 4. Hash函数与数字签名 【常考】
杂凑函数简称Hash函数，它能够将任意长度的信息转换成固定长度的哈希值(又称数字摘要或消息摘要)，并且任意不同消息或文件所产生的哈希值是不一样的。
# Hash算法【常考】
1. 常见的Hash算法有: MD5('128位的消息摘要'), SHA('160位的哈希值')和SM3('杂凑值长度为256比特').
# 数字签名【常考核心概念】
1. 数字签名(Digital Signature)是指签名者使用私钥对待签名数据的杂凑值做密码运算得到的结果。该结果只能用签名者的公钥进行验证，主要用于确认待签名数据的完整性、签名者身份的真实性和签名行为的抗抵赖性。
2. '数字签名至少应满足以下三个基本条件':
	(1) 非否认性: 签名者事后不能否认自己的签名，保证行为的不可抵赖性。
	(2) 真实性: 接收者能验证签名的合法性，而任何其他人都不能伪造签名，确保身份真实。
	(3) 可鉴别性: 当双方关于签名的真伪发生争执时，第三方(如仲裁机构)能解决双方之间发生的争执。
3. 一个完整的数字签名方案一般由签名算法和验证算法组成。签名算法密钥是秘密的，只有签名人掌握；而验证算法则是公开的，以便他人验证。典型的数字签名方案有 "RSA, Rabin, EIGamal签名体制和DSS标准"。
4. "签名与加密的核心区别辨析": 加密的目的是保护信息不被非授权用户访问，侧重保密性；而签名是使消息接收者确信信息的发送者是谁，以及信息是否被他人篡改，侧重真实性和完整性。
# 签名步骤
1. 第一步(Hash摘要): Alice使用Hash函数将电子合同文件生成一个唯一的消息摘要，确保摘要与文件一一对应；
2. 第二步(私钥加密): Alice使用自己的私钥，对消息摘要进行加密处理，形成数字签名。"此数字签名不可改变，否则即视为无效"。
3. 第三步(发送): Alice将原始电子合同文件与生成的数字签名一同发送给Bob，完成交付。
# 验证步骤
1. 第一步(重新计算): Bob收到文件后，使用Alice相同的Hash算法，独立计算所收到电子合同文件的消息摘要。
2. 第二步(解密恢复): Bob使用Alice的公钥，对收到的数字签名进行解密，恢复出Alice当初生成的原始消息摘要。
3. 第三步(对比校验): Bob将自己计算的摘要与恢复的摘要进行比对。若一致，证明文件真实为篡改；若不一致，则表面文件已被篡改或签名伪造。

# BLP 机密性模型 (下读上写) [口诀: 为了保密，小肚上写]
1. BLP模型有两个特性：简单安全特性（读）、*特性(写)。
	(1) 简单安全特性。主体对客体进行读访问的必要条件是主体的安全级别不小于客体的安全级别，主体的范畴集合包含客体的全部范		畴，'即主题只能向下读，不能向上读'。
	(2) *特性。一个主体对客体进行写访问的必要条件是客体的安全级支配主体的安全级，即客体的保密级别不小于主体的保密级别，客体的		范畴集合包含主体的全部范畴，'即主体只能向上写，不能向下写'。
2. 为了实现军事安全策略，计算机系统中的信息和用户都分配了一个访问类，在一个访问类中，仅有单一的安全级，而范畴可以包含多个。它由两部分组成：
	(1) 安全级: 对应诸如公开、密码、机密和绝密等名称；安全级的顺序一般规定为: '公开 < 密码 < 机密 < 绝密'。
	(2) 范畴集: 指安全级的有效领域或信息所归属的领域，如人事处、财务处等。两个范畴之间的关系是 '包含、被包含或无关'。
		举例: 文件F 访问类: {机密: 人事处，财务处};
			 用户A 访问类: {绝密: 人事处};
			 用户B 访问类: {绝密: 人事处，财务处，科技处}
		用户B可以阅读文件F，因为用户B的级别高，涵盖了文件的范畴。而用户A的安全级别虽然高，单不能读文件F，因为用户A缺少了财务		 处的范畴。
# BiBa 完整性模型 (上读下写) [口诀: 吃了biba, 上吐下泻]
1. BiBa模型主要用于防止非授权修改系统信息，以保护系统的西信息 '完整性'。
2. BiBa具有三个安全特性: '简单安全特性、*特性、调用特性'。
	(1) 简单安全特性。主体对客体进行修改访问的必要条件是主体的完整性级别小于客体的完整性级别，主体范畴集合保护客体的全部范畴，		即 '主体不能向下读'。
	(2) *特性: 主体的完整性级别不小于客体的完整性级别，不能修改客体，即 '主体不能向上写'。
	(3) 调用特性。主体的完整性级别小于另一个主体的完整性级别，不能调用另一个主体。
3. 信息流模型: 用于分析系统的隐藏通道，防止铭感信息通过敏感通道泄露。
# PDRR 信息保障模型
1. 美国国防部提出了 PDRR 模型，改进了传统的只有保护的单一安全防御思想，强调信息安全保障的四个重要环境。
	(1) '防护(Protection)'的内容主要有加密机制、数据签名机制、访问控制机制、认证机制、信息隐藏、防火墙技术等。
	(2) '检测(Detection)'的内容主要有入侵检测、系统脆弱性检测、数据完整性检测、攻击性检测等。
	(3) '恢复(Recovery)'的内容主要有数据备份、数据修复、系统恢复等。
	(4) '响应(Response)'的内容主要有应急策略、应急机制、应急手段、入侵过程分析及安全状态评估等。
2. 美国 ISS 公司提出的动态网络安全体系的代表模型。 P2DR模型的要素由 '策略(Policy)、防护(Protection)、检测(Detection)、响应(Response)构成'。
3. '区分：第一章网络应基本功能: 防御/监测/应急/恢复'
4. WPDRRC的要素由 '预警、保护、检测、响应、恢复和反击'构成。模型蕴涵的网络安全能力主要是预警能力、保护能力、检测能力、响应能力、恢复能力和反击能力。

# 网络生存模型

# 公钥基础设施 (PKI) 技术
1. PKI公开密钥基础设施是一个包括硬件、软件、人员、策略和规程的集合，用来实现基于公钥秘密体制的密钥和正式的产生、管理、存储、分发和撤销等功能。X.509是公钥基础设施(PKI)的标准格式。基于PKI的主要安全服务由身份认证、完整性保护、数字签名、会话加密管理、密钥恢复。
2. PKI产生的原因：公钥秘密体制实现加密、识别和认证服务。但直接使用公钥密钥算法存在较为严重的安全问题，即公钥的真实性和所有权问题。针对这些问题采用 "公钥证书" 来解决。公钥证书是将实体和一个公钥绑定，并让其他实体能够验证这种绑定关系。
3. PKI需要一个可信第三方来担保实体的身份，简称 CA (证书授权机构)。 'CA证书中含有实体名、公钥以及实体的其他身份信息'。
4. PKI 各实体的功能如下:
'(1) CA(Certification Authority): 证书授权机构，主要进行证书的颁发、废止和更新；认证机构负责签发、管理和撤销一组终端用户的证书.'
'(2) RA(Registration Authority): 证书登记权威机构，将公钥和对应的证书持有者的身份及其他属性联系起来，进行注册和担保；RA可以充当CA和它的终端用户之间的中间实体，辅助CA完成其他绝大部分的证书处理能力。'
'(3) 目录服务器: CA 通常使用一个目录服务器，提供证书管理和分发的服务。'
'(4) 终端实体(End Entity): 指需要认证的对象，例如服务器、打印机、E-mail地址、用户等'
'(5) 客户端(Client): 指需要基于PKI安全服务的使用者, 包括用户、服务进程等'

### 1. 访问控制类型【必考】

# 自主访问 【必考】【行主列客(基于行的在主体上附加)，行分能前令，列分护访】
1. 自主访问控制(DAC)是指 '客体的所有者按照自己的安全策略授予系统中的其他用户对其的访问权'。自主访问控制的实现方法有两大类，即 '基于行的自主访问控制和基于列的自主访问控制'。
优点: 访问机制简单、灵活；
缺点: 实现依赖用户的安全意识和技能，不能满足高安全等级的安全要求。
2. 基于行的自主访问控制方法是在'每个主体上'都附加一个该主体可访问的客体的明细表，根据表中信息的不同又可分成三种形式，即'能力表(capability list)、前缀表(profiles)和口令(password)'。（能力表一般是文件+权限、前缀表一般是目录/网络接口/打印机+权限）
3. 基于列的自主访问控制机制是在'每个客体上'都附加一个可访问它的主体的明细表，它有两种形式，即'保护位(protection bits)和访问控制表(Access Control List, ACL)'。（保护位:9位的rwx文件系统权限；ACL：主任/组/其他人/某用户:对某文件读、写、禁止访问）
# 强制访问控制
1. 强制访问控制(MAC)是指系统根据主体和客体的安全属性，以强制访问控制主体对客体的访问。与自主访问控制相比较，强制访问控制更加严格。'BLP和Biba模型都属于强制访问控制'。
# 基于角色的访问控制
1. 基于角色的访问控制(RBAC)是指根据完成某些职责任务所需要的访问权限来进行授权和管理。RBAC由'用户(U)、角色(R)、会话(S)和权限(P)'四个基本要素组成。

### 1. 防火墙概念【熟悉】
# 安全区域 Zone
1. 公共外部网络: 如Internet；
2. 内联网(Intranet): 如某个公司或组织的专用网络，网络访问限制在组织内部；
3. 外联网(Extranet): 内联网的扩展延伸，常用做组织与合作伙伴之间进行通信；
4. 军事缓冲区域，简称DMZ: 该区域是介于内部网络和外部网络之间的网络段，常放置公共服务设备，向外提供信息服务。
在安全区域划分的基础上，通过一种网络安全设备，控制安全区域间的通信，可以隔离有害通信，进而阻断网络攻击。俗称为“防火墙”。

### 2. 防火墙类型与实现技术【常考，掌握】
防火墙类型分为包过滤防火墙、代理防火墙、下一代防火墙、Web应用防火墙、数据库防火墙、工控防火墙。
# 包过滤防火墙
1. '包过滤是在IP层实现的防火墙技术'，包过滤根据包的源IP地址、目的IP地址、源端口、目的端口及包传递方向等包头信息判断是否允许包通过。
2. 包过滤是防火墙的基本功能之一。多数现代的IP路由软件或设备都支持包过滤功能，并默认转发所有的包。包过滤的控制依据是规则集，典型的过滤规则标识格式由 '规则号、匹配条件、匹配操作'三部分组成，一般的包过滤防火墙都用源IP地址、目的IP地址、源端口号、目的端口号、协议类型(UDP、TCP、ICMP)、通信方向、规则运算符来描述过滤规则条件。而匹配操作有 '拒绝、转发、审计' 三种。
# 状态检测技术
1. '采用状态检测技术的防火墙首先建立并维护一张会话表'，当有符合已定义安全策略的TCP连接或UDP流时，防火墙会创建会话项，然后依据状态表项检查，与这些会话相关联的包才允许通过防火墙。

# iptables四表
1. Filter表: Filter是iptables的默认表，它有以下三种内建链(chains): INPUT链--处理来自外部的数据。OUTPUT链--处理向外发送的数据。FORWARD链--将数据转发到本机的其他网络设备上。
2. NAT表: 包含三种链: prerouting链--处理刚到达本机并在路由转发前的数据包。它会转发数据包中的目标IP地址(destination ip address)，通常用于DNAT(destination NAT)。postrouting链--处理即将离开本机的数据包。它会转发数据包中的源IP地址(source ip address)，通常用于snat(source NAT)。output链--处理本机产生的数据包。
3. Mangle表: 用于指定如何处理数据包。它能改变TCP头中的Qos位。
4. Raw表: 用于处理异常。
# iptables五链
1. input链: 处理输入数据包
2. output链: 处理输入数据包
3. forward链: 处理转发数据包
4. prerouting链: 用于目标地址转换(dnat)
5. postouting链: 用于源地址转换(snat)
## IPtables规则【必须掌握】
规则的关键知识点: Rules包含一个条件和一个目标(target)，如果满足条件，就执行目标(target)中的规则或者特定值；如果不满足条件，就判断下一条Rules。
1. iptables基本语法如下: iptables [-t table] command [match] [-j target/jump]。其中[-t table]指定规则表，默认的是filter
2. filter: 这个规则表是默认规则表，拥有input, forward和output三个规则链，用来进行数据包过滤的处理动作(如drop, accept或reject等)，通常的基本规则都建立在此规则表中。
# 3-1. command常用命令列表 (以下命令中同一行的两个命令作用是同等的，写法上有区别)
	(1) -A: -append用于新增规则到某个规则链中，该规则将称为规则链中的最后一条规则。
	(2) -D: -delete用于从某个规则链中删除一条规则，可以输入完整规则，或直接指定规则编号加以删除。
	(3) -R: -replace用于取代现行规则，规则被取代后并不会改变顺序。
	(4) -I: -insert用于插入一条规则，原本该位置上的规则将会往后移动一个位置。
	(5) -F: -flush用于删除filter表中的input链的所有规则。
# 3-2. match常用数据包匹配参数
	(1) -p: protocol用于匹配通信协议类型是否相符, 可以用"!"运算符进行反向匹配，如-p! tcp的意思是指除tcp以外的其他类型，如		udp、icmp等非tcp的其他协议。如果要匹配所有类型，则可以使用all关键词。
	(2) -s: src, -source用来匹配数据包的来源IP地址(单机或网络)，匹配网络时用数字来表示子网掩码，如 -s 192.168.1.0/24，也可	  以使用"!"运算符进行反向匹配。
	(3) -d: -dst, --destination用来匹配数据包的目的IP地址。
	(4) -i: -in, -interface用来匹配数据包是从哪块网卡进入的，可以使用通配符"+"来做大范围匹配，如-i eth+表示所有的ethernet		  网卡，也可以使用"!"运算符进行方向匹配。
	(5) -o: -out, -interface用来匹配数据包要从哪块网卡送出。
	(6) --sport: -source-port用来匹配数据包的源端口，可以匹配单一端口或一个范围，如--sport22:80表示22~80之间都算是符合条		  件，如果要匹配不连续的多个端口，则必须使用-multiport参数。
	(7) --dport: -destination-port用来匹配数据包的目的地端口号。
# 3-3. -j target/jump常用的处理动作。
-j参数用来指定要进行的处理动作，常用的处理动作包括: accept, reject, drop, redirect, masquerade, log, snat, dnat等，如下:
	(1) accpt: 将数据包放行，进行完此处理动作后将不再匹配其他规则，直接跳往下一条规则链(natportrouting);
	(2) reject: 拦阻该数据包并传送数据包通知对方，进行完此处理动作后将不再匹配其他规则，直接中断过滤程序;
	(3) drop: 丢弃数据包不予处理，进行完此处理动作后将不在匹配其他规则，直接中断过滤程序;
	(4) redirect: 将数据包重新导到另一个端口(pnat)，进行完成处理动作后继续匹配其他规则;
	(5) log: 将数据包相关信息记录在/var/log中，进行完成此处理动作后将继续匹配其他规则。
示例:
	iptables -A INPUT -i eth0 -p tcp --dport 21 -j DROP
	丢弃所有通过tcp协议访问本机21端口的数据包
	iptables -A INPUT -i eth0 -p tcp -s 192.168.1.0/24 --sport 1024:65535 --dport ssh -j DROP
	丢弃来自192.168.1.0/24的1024:65535端口的访问本机ssh端口的数据包

第10章 入侵检测技术原理与应用 2-4

### 1. 入侵检测概述【有时考，熟悉】
1. 概念: 入侵检测通过收集操作系统、系统程序、应用程序、网络包等信息，发现系统中违背安全策略或危及系统安全的行为。具有入侵检测功能的系统称为入侵检测系统，检测为 'IDS'。
2. 作用: 发现受包含系统中的入侵行为或异常行为；检验安全保护措施的有效性；分析受保护系统所面临的威胁；有利于阻止安全事件扩大，及时报警触发网络应急响应；可以为网络安全策略的制定提供重要指导；报警信息可用作网络犯罪取证。
# 入侵检测模型
通用入侵检测框架模型CIDF由事件产生器、事件分析器、响应单元和事件数据库组成
1. '事件产生器从整个计算环境中获得事件，并向系统的其他部分提供事件;'
2. '事件分析器分析所得到的数据，并产生分析结构'
3. '响应单元对分析结构做出反应，如切断网络连接、改变文件属性、简单报警等应急响应'
4. '事件数据库存放各种中间和最终数据，数据存放的形式既可以是复杂的数据库，也可以是简单的文本文件'


### 2. 入侵检测技术【有时考，熟悉】
入侵检测实现技术，主要包括'基于误用'的入侵检测技术、'基于异常'的入侵检测技术和其他技术。
## 2.1 基于误用的入侵检测技术【基于特征。通缉犯的照片和指纹，一旦发现就会触发】
1. '误用入侵检测通常称为基于特征的入侵检测方法'，是指根据已知的入侵模式检测入侵行为。误用入侵检测依赖于攻击模式库。采用误用入侵检测技术的IDS产品的检测能力取决于攻击模型库的大小以及攻击方法的覆盖面。
# 误用检测方法
1. 基于条件概率的误用检测方法，是将入侵方式对应一个事件序列，然后观测事件发生序列，应用贝叶定理进行推理，推测入侵行为。
	(1)攻击真实概率(后验概率) = 发生入侵时出现事件序列的概率 X 历史统计的基础概率(先验概率) / 所有场景下出现事件序列的总概			率。
	(2)所有场景下出现事件序列额总概率 = [发生入侵时出现事件序列的概率 - 正常行为触发可疑序列的概率] x 历史统计的基础概率(先			验概率) + 正常行为触发可疑序列的概率。
2. 基于状态迁移的误用检测方法: 利用状态图表示攻击特征，通过检查系统的状态变化发现系统中的入侵行为。
3. 基于键盘监控的误用检查方法: 监测用户的击键模式，并将其与入侵模式匹配，从而发现入侵行为。
4. 基于规则的误用监测方法: 将攻击行为或入侵模式表示成一种规则，只要符合规则就认定它是一种入侵行为。大部分IDS采用的是这种方法。snort是典型的基于规则的误用检测方法的应用实例。
## 2.2 基于异常的入侵检测技术 【基于：统计、规则(顺序，操作)、】
1. 异常检测方法是通过计算机或网络资源统计分析，建立系统正常行为的 “轨迹”，定义一组系统正常情况的数值，然后将系统运行时的数值与所定义的正常情况相比较，得出是否有被攻击的迹象，这些迹象是异常行为集合。但要注意，异常行为集合通常不等同于入侵行为集合，所有会有误报。
# 几种常见的异常检测方法:
1. 基于统计的异常检测方法: 利用数字统计理论技术，通过构建用户或系统正常行为的特征轮廓。
2. 基于模式预测的异常检测方法: 根据观察到的用户行为归纳产生一套规则集，构成用户的行为轮廓框架。如果后续的事件显著地根据规则预测到的事件，那么系统就可以检测出这种偏离，表明用户操作异常。
3. 基于文本分类的异常检测方法: 将程序的系统调用视为某个文档中的 “字”，而进程运行所产生的系统调用集合就产生一个“文档”。对于每个进程所产生的“文档”，利用K-最近邻聚类文本分类算法，分析文档的相似性，发现异常的系统调用，从而检测入侵行为。
4. 基于贝叶斯推理的异常检测方法【先学习系统，再推断】: 在任意给定的时刻，测量A1 A2, ...An变量值，推理判断系统是否发生入侵行为。
## 2.3 其他检测方法
1. 基于规范的检测方法: 介于异常检测和误用检测，定义安全跟踪策略，若操作序列不符合定义就报警；
2. 基于生物免疫的检测方法: 模仿生物免疫机制，使受保护的系统能够将 “非自我” 的攻击行为与 “自我” 的合法行为区分开。
3. 基于攻击诱骗的检测方法: 提供虚假的系统或漏洞信息，如果入侵者应用这些信息攻击系统，就可以推断系统正在遭受入侵，并且安全管理员还可以诱惑入侵者，进一步跟踪攻击来源。
4. 基于入侵报警的关联检测方法：通过对原始的IDS报警事件的分类及相关性分析来发现复杂攻击行为。
5. 基于沙箱动态分析的检测方法: 通过构建程序运行的受控安全环境，然后监测可疑恶意文件或程序在安全沙箱的运行状况，获取可疑恶意文件或可疑程序的动态信息，最后检测相关信息是否异常，从而发现入侵行为。
6. 基于大数据分析的检测方法: 通过汇聚各种日志、情报、流量等多种数据资源，形成大数据资源池，然后利用人工智能技术，进行机器学习，以发现入侵行为。


### 3. 入侵检测系统组成与分类【有时考，熟悉】
## 入侵检测系统组成
入侵检测功能模块组成: '数据采集模块、入侵分析引擎模块、应急处理模块、管理配置模块和相关的辅助模块。'
1. 数据采集模块: 为入侵分析引擎模块提供分析用的数据，包括操作系统的审计日志、应用程序的运行日志和网络数据包等。
2. 入侵分析引擎模块: 依据辅助模块提供的信息（如攻击模式），根据一定的算法对收集到的数据进行分析，从中判断是否有入侵行为出现，并产生入侵报警。该模块是入侵检测系统的核心模块。
3. 管理配置模块: 为其他模块提供配置服务，是IDS系统中的模块与用户的接口。
4. 应急处理模块: 发生入侵后，提供紧急响应服务（'教材模棱两可'），例如关闭网络服务、中断网络连接、启动备份系统等。
5. 辅助模块: 协助入侵分析引擎模块工作，为它提供相应的信息，例如攻击特征库、漏洞信息等。
## IDS分为三大类
1. 第一类是基于主机的入侵检测系统 (简称HIDS);
2. 第二类是基于网络的入侵检测系统 (简称NIDS);
4. 第三类是分布式入侵检测系统 (简称DIDS)，从多台主机、多个网络采集检测数据。
# HIDS一般适合检测基于系统的入侵行为
1. 优点: 检测网络 IDS 检测不到的、可运用加密网络；
2. 缺点: 需要主机安装、占用资源、易受攻击
3. 'HIDS软件举例: (1)SWATCH  (2)Tripwire  (3)网络防篡改系统'
# NIDS能够检测到基于网络的入侵行为
1. 优点: 监控范围大、不影响网络、攻击者不可见；
2. 缺点: 性能原因漏检、受网络条件限制、加密流量无法分析、无法判断攻击是否成功。

1. 开源IDS系统Snort: 网络型误用检测系统，基本技术原理是通过获取网络数据包，基于安全规则进行入侵检测，形成报警信息。
2. Snort规则由两部分组成，即规则头和规则选项。规则头包含规则操作(action)、协议(protocol)、源地址和目的IP地址及网络掩码、源地址和目的端口号信息。规则选项包含报警消息、被检查网络包的部分信息及规则应采取的动作
# Sort配置为以三种模式运行
1. '嗅探模式: 从网络中读取数据包并在控制台(屏幕)上以连续流的形式显示';
2. '数据包记录器模式: 将数据包记录到磁盘。可以用 -l 命令来把日志存到一个目录下，比如 -l ./log'
3. '网络入侵检测(NIDS)模式: 对网络流量进行检测和分析。这是最复杂和可配置的模式。'
# Snort规则示例
alert tcp any any -> $HOME_NET $HTTP_PORTS (msg:"SQL injection Attack"; content:"or '1'='1'"; nocase; classtype:web-application-attack; sid: 100001;)
(1) 规则头和规则选项通过 "()" 来区分，规则选项内容用括号括起来.
动作有 alert, log, pass, activate, dynamic, 这里是 alert
    Alert-使用选择的报警方法生成一个警报，然后记录 (log) 这个包。
	Log-只记录不告警。
	Pass-匹配的数据包合法，不进行进一步处理和告警。
	activate-报警并且激活另一条dynamic规则。
	dynamic-保持空闲直到被一条activate规则激活，被激活后就作为一条log规则执行。
(2) 协议tcp, udp, icmp和ip等，这里是tcp
(3) 地址、端口: 这里是any any, 即匹配任意源ip和任意源端口的数据包
(4) -> 规则的方向部分，指定数据包的流向，箭头指向右边表示数据包的目的地，也可以双向。
(5) $HOME_NET: 这是一个预定义的snort变量，表示本地网络。可以在配置文件中定义和修改这个配置。
(6) $HTTP_PORTS: 这是另一个预定义的Snort变量，表示HTTP协议的端口号。同样可以定义和修改。
(7) msg: "SQL Injection Attack": 这是警报消息部分，表示当规则匹配时生成的警报消息。
(8) content: "' Or'1'='1": 这是规则的内容匹配部分，表示匹配数据包是否包含指定的内容，即SQL注入攻击的特定字符串。
(9) nocase: 这是一个选项，表示匹配时不区分大小写。
(10) classtype: web-application-attack: 这是规则的类目，指定规则所属的攻击类型，这里是Web应用程序攻击。
(11) sid: 100001: 这是规则的唯一标识符部分，用于标识规则的唯一性。
总结: 当Snort检测到TCP协议的任意源IP和源端口的数据包，目的地是本地网络的HTTP端口，并且数据包中包含了SQL注入攻击的特定字符时，Snort将生成一个警报，警报消息为"SQL Injection Attack"，并将该规则分类为Web应用程序攻击，唯一标识为100001

### 网络物理隔离机制与实现技术【常考，熟悉】
# 物理隔离机制的实现技术，主要包括专用计算机上网、多PC、外网代理服务、内外网线路切换器、单硬盘内外分区、双硬盘、网闸、协议隔离、单向传输、信息摆渡、物理断开等技术。
1. 专用计算机上网: 在内部网络中指定一台计算机，这台计算机只与外部网络相连，不与内部网相连。用户必须到指定的计算机才能上网，并要求用户离开自己的工作环境。
2. 多PC: 内网网络中，在上外网的用户桌面上安装两台PC，分别连接两个分离的物理网络，一台连接外部网络，另一台连接内部网络。
3. 外网代理服务: 在内部网指定一台或多台计算机充当服务器，负责专门搜集外部网的指定信息，然后把外网信息手工导入内部网，供内部用户使用，从而实现内部用户“上网”，又切断内网与外网的物理连接，避免内网的计算机收到来自外网的攻击。
4. 内外网线路切换器: 在内部网中，上外网的计算机连接上一个物理线路A/B交换盒，通过开关设置控制计算机的网络物理连接。
5. 单硬盘内网分区: 把单一硬盘隔成不同的区域，在IDE总线物理上，通过一块IDE总线信号控制卡截取IDE总线信号，控制磁盘通道的访问，在任一时间内，仅允许操作系统访问指定的分区。
6. 双硬盘: 在一台机器上安装两个硬盘，通过硬盘控制卡对硬盘进行切换控制，用户在连接外网时，挂载外网硬盘，而当用内网办公时，挂接内部网办公硬盘。
7. '网闸'通过利用一种GAP技术 (源于英文的Air Gap)，使两个或两个以上的网络在不连通的情况下，实现它们之间的安全数据交换和共享。
8. 协议隔离技术: 处于不同安全域的网络在物理上是有连续的，通过协议转换的手段保证受保护信息在逻辑上是隔离的，只有被系统要求传输的、内容受限的信息可以通过。其中，协议转换的定义是协议的剥离和重建。把基于网络的公共协议中的应用数据玻璃出来，封装为系统专用协议传递至所属其他安全域的隔离产品另一端，再将专用协议玻璃，并封装成需要的格式。
9. 单向传输部件: 一对具有物理上单向传输特性的传输部件，该传输部件由一对独立的发送和接收部件构成，发送和接收部件只能以单工方式工作，发送部件仅具有单一的发送功能，接收部件仅具有单一的接收功能，两者构成可信的单向信道，该信道无任何反馈信息。
10. 信息摆渡技术: 信息传输时，信息先由信息源所在安全域一端传输至中间缓存区域，同时物理断开中间缓存区域与信息目的所在安全域的连接，随后接通后中间缓存区域与信息目的所在安全域的传输信道，将信息传输至信息目的所在安全域，同时在信道上物理断开信息所在安全域与中间缓存区域的连接。在任何时刻，中间缓存区域只与一端安全域相连。
11. 物理断开技术: 处于不同安全域的网络之间不能以直接或间接地方式相连接。在一个物理网络环境中，实施不同安全域地网络物理断开，在技术上应确保信息在物理传导、物理存储上地断开。物理断开通常由电子开关来实现。
# 物理隔离主要产品
1. 终端隔离产品: 终端隔离产品用于同时连接两个不同地安全域，采用物理断开技术在终端上实现安全域物理地安全隔离卡或安全隔离计算机
2. 网络隔离产品: 用于连接两个不同地安全域，实现两个安全域之间地应用代理访问、协议转换、信息流访问控制、内容过滤和信息摆渡等
3. 网络单向导入产品: 位于两个不同地安全域之间，通过物理方式（可基于电信号传输或光信号传输）构造信息单向传输的唯一通道，实现信息单向导入，并保证只有安全策略允许传输的信息可以通过，同时反方向无任何西悉尼的传输或反馈。
# 网络和终端隔离产品的技术指标主要有: 安全功能指标、安全保障指标、性能指标。
1. 终端隔离产品的功能要求: 访问控制、不可旁路和客体重用；
2. 网络隔离差评的功能要求：访问控制、抗攻击、安全管理、标识和鉴别、审计、域隔离、容错、数据完整性和密码支持
3. 网络单向导入的功能要求: 访问控制、抗攻击、安全管理、标识和鉴别、审计、域隔离、配置数据保护和允许状态监测。

### 0. 网络安全审计概述【了解】
网络安全审计是指对网络信息系统的安全相关活动信息进行获取、记录、存储、分析和利用的工作。网络安全审计的作用在于建立 “事后” 安全保障措施。IT产品和安全设备都不同程度地提供安全审计功能，重要系统部署独立的网络安全设计系统。

# 系统日志数据采集技术
常见的系统日志数据采集技术是把操作系统、数据库、网络设备等系统中产生的事件信息汇聚到统一的服务器存储，以便于查询分析与管理。目前，常见的系统日志数据采集方式有Syslog、SNMPTrap(SNMP是服务端轮询客户端， SNMPTrap是客户端主动推送给服务端)等。
# 网络流量数据获取技术
1. 网络流量数据获取技术是网络通信安全审计的关键技术之一，常见的技术方法有共享网络监听、交换机端口镜像(Port Mirroring)、网络分流器(Network Tap)等。

3. 对于不支持端口镜像功能的交换机，通常利用网络分流器(TAP)把网络流量导入网络流量采集设备。

1. Libpcap (Library for Packet Capture)网络数据包捕获软件，支持不同平台使用;
2. Winpcap支持再Windows平台捕获网络数据包;
3. Windump是基于Winpcap的网络协议分析工具，可以采集网络数据包;
4. Tcpdump是基于Libpcap的网络流量数据采集工具, 常常应用于Linux操作系统中；
5. Wireshark是图形化的网络流量数据采集工具, 可用于网络流量数据的采集和分析。
# 网络审计数据安全分析技术
网络审计数据需要通过数据分析技术来提取。如: 字符串匹配、全文搜索、数据关联、统计报表、可视化分析等。
1. 字符串匹配: 通过模式匹配来查找相关审计数据，以便发现安全问题。常见的字符串匹配工具grep使用的格式: 用来标识要搜索的匹配模式
2. 全文搜索: 利用搜索引擎技术来分析审计数据。开源搜索引擎工具Elastic search常用作数据分析;
3. 数据关联: 将网络安全威胁情报信息，如系统日志、全网流量、安全设备日志等多个数据来源进行综合分析；
4. 统计报表: 对安全审计数据的特定事件、阈值、安全基线等进行统计分析生成告警信息，形成发送日、周、月报；
5. 可视化分析: 将审计数据进行图标化处理，形成饼图、柱状图、折线图、地图等各种可视化效果，支持各种场景。
# 网络审计数据存储技术
网络审计数据存储技术分为两种:
1. 系统分散存储，审计数据保存在不同的系统中;
2. 集中采集, 建立审计数据存储服务器，由专用的存储设备保存，便于时候查询分析和电子取证。
# 网络审计数据保护技术
1. '系统用户分权管理': 操作系统、数据库等系统设置'操作员、安全员和审计员'三种类型的用户。操作员只负责系统的操作维护工作，操作过程被系统进行了详细记录；安全员负责系统安全策略配置和维护；审计员负责维护审计相关事宜，可以查看操作员、安全员工作日志；操作员不能够修改自己的操作记录，审计员不能对系统进行操作。 
2. '审计数据强制访问': 采取强制访问控制措施，对审计数据设置安全标记，防止非授权用户查询及修改审计数据。
3. '审计数据加密': 使用加密技术对敏感的审计数据进行加密处理，以防止非授权查看审计数据或泄露。
4. '审计数据隐私保护': 采取隐私保护技术，防止审计数据泄露隐私信息。
5. '审计数据完整性保护': 使用Hash算法和数字签名对审计数据进行数字签名和来源认证、完整性保护，防止非授权修改审计数据。目前，Hash算法主要有MD5、SHA、国产SM3算法等。国产SM2/SM9可用于对审计数据签名。

### 2. 网络安全漏洞分类与管理【常考，熟悉】
## 网络信息系统的漏洞主要来自两个方面:
1. 非技术性安全漏洞: 管理组织结构、管理制度、管理流程、人员管理等;
2. 技术性安全漏洞: 网络结构、通信协议、设备、软件产品、系统配置、应用系统等。
# 非技术安全漏洞的主要来源--5不1缺失
1. 网络安全责任主体不明确;
2. 网络安全策略不完备；
3. 网络安全操作技能不足;
4. 网络安全监督缺失;
5. 网络安全特权控制不完备。
# 技术性安全漏洞的主要来源:
1. 设计错误: 由于系统或软件程序设计错误而导致的安全漏洞。
2. 输入验证错误: 由于未对用户输入数据的合法性进行验证，使攻击者非法进入系统。
3. 缓冲区溢出: 输入程序缓冲区的数据超过其规定长度，造成缓冲区溢出，破坏程序正常的堆栈，使程序执行其他代码。
4. 意外情况处置错误: 由于程序在实现逻辑中没有考虑到一些意外情况，而导致运行错误。
5. 访问验证错误: 由于程序的访问验证部分存在某些逻辑错误，使攻击者可以绕过访问控制进入系统。
6. 配置错误: 由于系统和应用的配置有误，或配置参数，访问权限、策略按照位置有误。
7. 竞争条件: 由于程序处理文件等实体在时序和同步方面存在问题，存在一个短暂的时机使攻击者能够施以外来的影响。
8. 环境错误: 由于一些环境变量的错误或恶意设置造成的安全漏洞。
## 网络安全漏洞分类与管理
# 国际上较为认可的是CVE和CVSS。另外，还有我国信息安全漏洞分类及OWASP漏洞分类。
1. CVE漏洞分类: 美国MITRE公司建设和维护的安全漏洞字典。给出统一标识和规范化描述，CVE条目的保护内容是标识数字、安全漏洞简要描述。标识数字简称CVE ID, 其格式由年份数字和其他数字组成，如CVE-2019-1543为一个Open SSL安全漏洞编号。
2. CVSS: 通用漏洞计分系统，分数计算依据由基本度量计分、时许度量计分、环境度量计分组成。
3. CNNVD(国家信息安全漏洞库): 将信息安全漏洞划分为: '配置错误、代码问题、资料不足'。
4. CNVD(国家信息安全漏洞共享平台): 根据漏洞产生原因，将漏洞分为11中类型； 依据行业划分主要分为行业漏洞和应用漏洞。在漏洞分级方面，将网络安全漏洞划分为高、中、低三种危害基级别。
5. OWASP(开放式Web应用程序安全项目): 组织发布有关Web应用程序的前十种安全漏洞。
6. CWE是软件安全弱点的分类框架，描述漏洞的通用成因和类型；CVE是具体漏洞实例的标识系统，为每个已知漏洞分配唯一ID。均由MITRE公司管理，CEW是CVE的补充。

## 网络安全漏洞扫描
# 具有漏洞扫描功能的软件或设备，简称为漏洞扫描器。漏洞扫描器通过远程或本地检查系统是否存在已知漏洞。
具体模块功能: 用户界面、扫描引擎、漏洞扫描结果分析、漏洞信息及配置参数库。
# 漏洞扫描器主要分为三种：即主机漏洞扫描器、网络漏洞扫描器、专门漏洞扫描器。
1. 主机漏洞扫描器: 通过检查本地系统中关键性文件的内容及安全属性来发现漏洞，主机漏洞扫描器的运行与目标系统在同一主机上，并且只能进行单机监测。主机漏洞扫描器有COPS、Tiger、Microsoft Baseline Security Analyser (MBSA)等
2. 网络漏洞扫描器: 通过与待扫描的目标机建立网络连接后，发送特定网络请求进行漏洞检查。常见的网络漏洞扫描器有Nmap、Nessus、X-scan等。
3. 专用漏洞扫描器: 针对特定系统的安全漏洞检查工具，如数据库漏扫、网络设备漏扫、Web漏扫、工控漏扫。

### 4. 网络安全漏洞处理技术与应用【有时考，熟悉】
1. 网络安全漏洞处置使网络安全应急响应的重要工作。主要有漏洞发现技术、漏洞修补技术、漏洞利用防范技术。 
2. 网络安全漏洞的发现方法主要依赖于人工安全性分析、工具自动化监测及人工智能辅助分析。
3. 网络安全漏洞修补技术: 补丁管理是一个系统的、周而复始的工作，主要由六个环节组成，现状分析、补丁跟踪、补丁验证、补丁安装、应急处理和补丁检查。
4. 网络安全漏洞利用防范技术: 主要针对漏洞触发利用的条件进行干扰或拦截，以防止攻击者成功利用漏洞。
# 网络安全漏洞发现常见工具
1. Flawfinder: 利用词法分析技术发现以C语言编写的源程序安全漏洞;
2. Splint: 检查以C语言编写的程序安全漏洞;
3. ITS4: 检查以C和C++语言编写的源程序安全漏洞;
4. Grep: 自定义漏洞模式，检查任意源程序安全漏洞;
5. MOPS: 利用状态机技术来分析以C语言编写的源程序安全漏洞
6. W3AF: Web应用程序漏洞验证;
7. Wireshark: 网络数据包分析软件;
8. Metasploit: 网络安全漏洞验证软件；
9. OllyDBG: 分析调试器。
# 常见的网络安全漏洞利用防范技术:
1. 地址空间随机化技术ASLR: 通过对程序加载到内存的地址进行随机化处理，使得攻击者不能事先确定程序的返回地址值，从而降低攻击成功的概率。
2. 数据执行阻止: 操作系统通过对特定的内存区域标注为非执行，使得代码不能够在指定的内存区域运行。可以有效保护应用程序的堆栈区域，防止被攻击者利用。
3. SEHOP：结构化异常处理覆盖保护的缩写，其原理是防止攻击者利用结构化异常处理(SEH)重写。
4. 堆栈保护: 通过设置堆栈完整性标记以监测函数调用返回地址是否被篡改，阻止攻击者利用缓冲区漏洞。
5. 虚拟补丁: 对尚未进行漏洞永久补丁修复的目标系统程序，在不修改可执行程序的前提下，监测进入目标的网络流量而过滤掉漏洞攻击数据包，从而保护目标系统程序免受攻击。

### 1. 恶意代码概述【有时考，熟悉】
## 恶意代码定义和分类
1. 恶意代码是一种违背目标系统安全策略的程序代码，会造成目标系统信息泄露、资源滥用，破坏系统的完整性及可用性。
2. 恶意代码的种类主要包括计算机病毒(Computer Virus)、蠕虫(Worms)、特洛伊木马(Trojan Horse)、逻辑炸弹(Logic Bombs)、细菌(Bacteria)、恶意脚本(Malicious Scripts)和恶意ActiveX控件、间谍软件(Spyware)等。
## 恶意代码攻击模型
# 恶意代码的作用机制大概分为以下6个步骤:
1. 第一步，入侵系统
2. 第二步，维持或提升已有的权限
3. 第三步，隐藏
4. 第四步，潜伏
5. 第五步，破坏
6. 第六步，重复前面5步对新的目标实施攻击过程。
## 扩展知识: 恶意代码标识一般格式未: <病毒前缀>.<病毒名>.<病毒后缀>
# 前缀分类
1. 系统病毒: VIRUS, PE
2. 若虫病毒: Worm
3. 木马病毒、黑客病毒: 木马病毒前缀是: Trojan, 黑客病毒前缀名一般为Hack
4. 脚本病毒: Script、VBS、JS
5. 宏病毒: Macro, 第二前缀是: Wrod、Word97、Excel、Excel97
6. 后面病毒: Backdoor
7. 病毒种植程序病毒: Dropper。运行时会从体内释放出一个或几个新的病毒，由释放出来的新病毒产生破坏。
8. 破坏性程序病毒: Harm。诱惑用户点击，直接破坏，如格式化硬盘。
9. 玩笑病毒: Joke
10. 捆绑机病毒: Binder。与正常程序捆绑
11. 其他: Dos: 会针对某台主机或服务器进行Dos攻击；Exploit: 会自动通过溢出对方或者自己的系统漏洞来传播自身，或者他本身就是一个用于Hacking的溢出工具; HackTool: 黑客工具。
## 恶意代码生存技术
1. 反跟踪技术: 提高自身的伪装能力和防破译能力，使检测与清除恶意代码的难度大大增加。反跟踪技术大致可以分为两大类: 反动态跟踪技术和反静态分析技术。
	(1) 反动态跟踪技术: 禁止跟踪中断、检测跟踪法、其他反跟踪技术。
	(2) 反静态分析技术: 对程序代码分块加密执行、伪指令法。
2. 加密技术: 恶意代码自我保护的手段，再配合反跟踪技术的使用，让分析者不能正常调试和阅读恶意代码，无法获得恶意代码的工作原理，不能抽取特征串。加密手段有三种，信息加密、数据加密和程序代码加密。
3. 模糊变换技术: 感染客体对象时使潜入宿主程序的代码不尽相同。只采用基于特征的检测工具一般无法有效识别他们。模糊变换技术主要分为以下几种：指令替换技术、指令压缩技术、指令扩展技术、伪指令技术、重编译技术。
4. 自动生产技术：普通病毒能够利用“多态性发生器”编译成具有多态性的病毒。多态变换引擎能够让程序代码产生改变，但却可以保持原有功能。
5. 变形技术：具有同一功能不同特征码的恶意代码。这种变换恶意代码特征码的技术称为变形技术。常见的恶意代码变形技术包括如下几个方面：重汇编技术、压缩技术、膨胀技术、伪指令技术。
6. 三线程技术: 防止恶意代码被外部操作停止运行。工作原理是同是开启了三个线程，一个为负责远程控制工作的主线程，两外两个监视线程负责检测恶意代码程序是否被删除或被停止自启动的监视线程和守护线程。
7. 进程注入技术: 在系统启动时操作系统的系统服务和网络服务一般能够自动加载。
8. 通信隐藏技术: 实现恶意代码的通信隐藏技术一般有四类:
	- 端口定制技术: 旧木马几乎都存在预设固定的监听端口，但是新木马一般都有定制端口的功能。
	- '端口复用技术: 木马Executor用80端口传递控制信息和数据: Blade Runner、Doly Trojan、Fore、FTP Trojan、Larva、eBex、		WinCrash等木马复用21端口；Shtrilitz Stealth、Terminator、WinPC、WinSpy等木马复用25端口'
	- 通信加密技术: 将恶意代码的通信内容加密发送。
	- 隐藏通道技术: 有效隐藏通信内容和通信状态，常见的能提供隐藏通道方式进行通信的后门有: BO2K，Code Red II， Nimida和			Covert TCP等。
9. 内核隐藏技术:
	- LKM隐藏: LKM是可加载内核模块，能够在不用重新编译内核的情况下把动态加载到内存中。LKM Rootkit通过系统提供的接口加载到内		核空间，将恶意程序转化成内核的某一部分，再通过hook系统调用的方式实现隐藏功能。
	- 内存映射隐藏：内存映射是指由一个文件到一块内存的映射。内存映射可以将硬盘上的内容映射至内存中，用户可以通过内存指令读写文		件。
## 恶意代码工具技术
1. 进程注入技术: 将与服务相关的嵌入了恶意代码程序的可执行代码作为载体，实现自身隐藏和启动的目的。
2. 超级管理技术: 采用超级管理技术对反恶意代码软件系统进行拒绝服务攻击，阻碍反恶意代码软件的正常运行。例如，“广外女生”是一个国产特洛伊木马，对“金山毒霸”和“天网防火墙”采用超级管理技术进行拒绝服务攻击。
3. 端口反向连接技术: 指令恶意代码使用端口反向连接技术使攻击的服务端（被控制端）主动连接客户端（控制端）端口。最早实现这项技术的木马程序是国外“Boinet”，它可以通过IO、IRC、HTTP和反向主动连接这4种方式连续客户端。“网络神偷”是我国最早实现端口反向连接技术的恶意代码。“灰鸽子”则是这项技术的集大成者，它内置FTP、域名、服务端主动连接这3种服务端在线通知功能。
4. 缓冲区溢出攻击技术: 攻击代码以一定的权限运行由缓冲区溢出漏洞的程序来获得被攻击主机的控制权。缓冲区溢出攻击称为恶意代码从被动式传播转为主动式传播的主要途径之一。例如，“红色代码”利用IIS Server 上Indexing Service的缓冲区溢出漏洞完成攻击、传播和破坏等恶意目的。
## 恶意代码分析技术
1. 静态分析方法有反恶意代码软件的检查、字符串分析、脚本分析和静态反汇编分析、静态反编译分析等；
2. 动态分析方法
	- 文件监测: 恶意代码执行后，在目标主机上可能读写各文件，修改程序，添加文件，甚至把代码嵌入其他文件，因此对文件系统必须进行监测。fileMon是常用的文件监测程序，能够记录与文件相关的动作，例如打卡、读取、写入、关闭、删除和存储时间戳等。另外还有文件完整性监测工具，如Trip wire、AIDE等。
	- 进程监测: 主机上所有被植入进程的细节都能为分析恶意代码提供重要参考信息。常用的进程监测工具是Process Explorer，它将机器上的每一个执行种的程序显示处理。
	- 网络活动监测:TCPView(linux&window: 查看端口和线程); Fport(windows:查看本机开发端口，以及端口和进程对应关系); Nmap(Linux&Windows:开源的扫描工具，用于系统管理员查看一个大型的网络有哪些主机，以及其上运行何种服务，支持多种协议的扫描);Nessus(Linux&windows: Nessus是一款经典的安全评估软件，功能强大且更新块，采用C-S模式，服务器端负责进行安全检查，客户端用来配置管理服务器端)。
	- 注册表监测: 恶意代码运行时一般改变Windows操作系统的配置来改变Windows操作系统的行为，实现恶意代码自身的目的。常用的监测软件是Regmon，它能够实现显示读写注册表项的全部动作。
	- 动态反汇编分析: 该监测过程从代码的入口点处开始，控制权在程序代码与调试工具之间来回传递，直到程序执行完为止。如OllyDbg、IDA Rro、SoftICE。

# 计算机病毒常见类型与技术
1. 引导型病毒: 通过感染计算机系统的引导区而控制系统，典型的有磁盘杀手病毒、AntiExe病毒等；
2. 宏病毒(Macro Viruses): 利用宏语言来实现的计算机病毒。能够感染任何运行office的计算机。
3. 多态病毒(Polymorphic Viruses): 多态病毒每次感染新的对象后，通过更换加密算法，改变其存在形式。
4. 隐藏病毒(Stealth Viruses): 将自身的存在形式进行隐藏，使得操作系统和反病毒软件不能发现。隐藏病毒使用的技术主要包括：隐藏文件的日期、时间的变化；隐藏文件大小的变化；病毒加密。


### 3. 特洛伊木马分析与防护【常考，熟悉】
1. '特洛伊木马(Trojan Horse,简称木马)是具有伪装能力、隐藏执行非法功能的恶意程序，而受害用户表面上看到的是合法功能的执行。特洛伊木马不具有自我传播能力，而是通过其他的传播机制来实现。'

4. '负载模块': 网络蠕虫内部的实现伪代码。
# 网络蠕虫扫描技术：'随机扫描、顺序扫描、选择性扫描'。

### 1. 入侵阻断技术与应用【有时考，熟悉】 *
1. 入侵阻断技术原理: 入侵阻断的基本原理是通过对目标对象的网络攻击行为进行阻断，从而达到保护目标对象的目的。
2. 入侵防御系统(IPS)的工作基本原理是根据网络包的特征以及上下文进行攻击行为判断来控制包转发，工作机制类似于路由器或防火墙，但IPS能够进行攻击行为检测，并能阻断入侵行为。
3. IPS通常用硬件方式来实现，如基于ASIC来实现，或者基于旁路阻断(SPS)来实现。
# IPS/SPS的主要安全功能如下：
1. '屏蔽指定IP地址';
2. '屏蔽指定网络端口';
3. '屏蔽指定域名';
4. '封锁指定URL、阻断特定攻击类型';
5. '为零日漏洞(Zero-day Vulnerabilities)提供热补丁'.

### 2. 软件白名单技术与应用【了解】
1. 利用软件进程名字、文件名词、发行商名词、二进制程序等相关信息经过密码技术处理后，形成软件白名单身份标识，如软件'数据签名或软件Hash值'。然后，在此基础商进行软件白名单身份检测确认，依据检测结果来控制软件的运行。

### 3. 网络流量清洗技术与应用【了解】
1. 技术原理: 通过异常网络流量监测，将原本发送给目标设备系统的流量牵引到流量清洗中心，当异常流量清洗完毕后，再把清洗后留存的正常流量转送到目标设备系统。
# 网络流量清洗技术应用主要场景:
1. 畸形数据报文过滤；
2. 抗拒绝服务攻击；
3. Web应用保护；
4. DDos高防IP服务。

### 4. 可信计算机技术与应用【了解】
1. 可信计算平台的信任根包括三个根: 可信度量根RTM、可信存储根RTS、可信报告根RTR。
2. 中国基于自主密码算法建立以 'TCM' 为核心的自主可信计算标准体系。该平台主要由可信密码模式(TCM)和TCM服务模块(TSM)两个组成。

1. 委托受理: 售前与委托单位就渗透测试项目进行前期沟通，签署“保密协议”，接收被测单位提交的资料。前期沟通结束后，双方签署“网络信息系统渗透测试合同”。

4. 综合评估阶段：项目组和客户沟通测试结果，向客户发送“网络信息系统渗透测试报告”。必要时，可根据客户需要召开报告评审会，对“网络信息系统渗透测试报告”进行评审。如被测单位希望复测，由被测单位在整改完成后提交信息系统整改报告，项目组依据“网络信息系统渗透测试整改报告”开展复测工作。复测结束后，依据复测结果，出具“网络信息系统渗透测试复测报告”。
5. 结题阶段：项目组将测评过程中生成的各类文档、过程记录进行整理，并交档案管理员归档保存。项目组质量工作人员请客户填写“满意度调查表”，收集客户反馈意见。

# 对称密码 (Symmetric Cryptography)
- 核心: 加密=解密密钥(Kc=Kd)
- 特征: 运算速度极快，适合大数据加密；密钥分发难

# 非对称密码 (Asymmetric Cryptography)
- 核心: 公钥加密，私钥解密 (Pk!=Sk)
- 特征: 解决密钥分发难题，支持数字签名；速度较慢
- 代表: RSA(通用), ECC(移动端), 国密SM2

## 02 按明文处理形式分类
# 流密码 (Stream Cipher) - 逐位加密
- 原理: 像水流一样逐比特处理，实时性强
- 核心: 生成伪随机密钥流，与明文做"异或(XOR)"运算
- 应用: 无线通信、实时数据加密；代表: RC4，祖冲之ZUC
# 分组密码 (Block Cipher) - 分块加密
- 原理: 将明文切成固定长度的块(如64/128位)独立加密
- 机制: 基于混淆(替代)或扩散(置换)设计, 需填充(Padding)确保长度符合要求
- 应用: 文件存储、数据加密标准；代表: AES, SM4, DES
# 关键关联与互通
- 范畴归属: 对称密码体系包含“流密码”和“分组密码”两种形态，而非对称密码无此划分。
- 模式转换: 分组密码可通过CTR(计算器模式)、OFD(输出反馈模式)等工作模式，生成连续密钥流，从而模拟流密码的特征，实现高效的流加密。

### Windows日志审计
# 日志分类
Windows主要有三类日志记录系统事件: '系统日志、应用程序日志和安全日志'
1. 系统日志(System Log) -- 底层运行的 “体检表”
记录操作系统内核、硬件驱动、系统服务的关键事件（如驱动加载失败、硬件故障、IP冲突、服务启停异常）。是排查系统级故障的核心线索，默认存储路径: %SystemRoot%\System32\Winevt\Logs\System.evtx
2. 应用程序日志(Application Log) -- 业务运行的 “记录仪”
由应用软件/服务主动写入，记录程序崩溃、数据库连接失败、功能调用异常等业务层事件。是定位软件故障的直接依据，默认存储路径:
%SystemRoot%System32\Winevt\Logs\Application.evtx
3. 安全日志(Security Log) -- 合规审计的 “铁证”
记录用户登录/注销、权限变更、文件访问、账号管理、策略修改等安全敏感行为。默认需要通过组策略/注册表手动开启，是网络攻击取证、权限审计的核心证据，默认存储路径 %SysstemRoot%System32\Winevt\Logs\Security.evtx
4. 运维要点: 需定期归档日志防止覆盖，同时开启安全日志审计策略，避免因日志缺失导致审计日志盲区。
# 日志状态
Windows日志将记录事件的5种状态，所有的事件必须拥有5种状态中的一种。5种事件状态分为:
1. 信息(Information): 记录应用程序、驱动或服务的正常成功操作，属于系统运行的常规反馈，无异常风险。
2. 告警(Warning): 表示存在潜在问题或关键故障，若不处理可能引发后续异常。例如：磁盘空间不足、打印机连接失败等非致命问题。
3. 错误(Error): 记录已经发生的严重故障，通常伴随功能失效或数据丢失风险。例如：系统服务启动失败、关键驱动加载异常等。
4. 成功审计(Success Audit): 属于安全日志范畴，记录通过验证的敏感操作，如用户成功登录系统、权限变更失效、文件访问授权通过等合规行为。
5. 失败审计(Failure Audit): 记录未通过安全验证的操作尝试，是发现入侵或违规行为的重要线索。例如：密码错误的登录尝试、非法访问共享文件的请求等。
## 日志事件ID与类型
Windows事件日志中，关键要素包括事件级别、记录时间、事件来源、事件ID、事件描述、涉及的用户、计算机、操作代码及任务类别等。

## Linux文件系统核心特性

# 文件的类型
1. d (directory)目录文件
2. l (link)符号文件。分为 '软链接' (ln -s) 和 '硬链接'。软件链接相当于快捷键，硬链接是“同名分身”
3. s (socket)套接字文件。不同主机之间的数据通信。这类文件常见于 /var/run 目录下
4. b (block)块设备文件。简单而言就是硬盘。为了提供读/写效率，它们都是以块(1024字节)为单位操作。比如硬盘、U盘等。
5. c (character)字符设备文件。是字符设备驱动程序在上层的表现形式，如键盘、鼠标等。
6. p (pipe)命名管道文件。主要用于实现同一主机内不同进程（程序）之间的通信。
7. -普通文件, 大多数文件的最常见类型，如文本、可执行文件、图片、视频等。
# Linux的主要目录
1. '/': '根目录，所有其他文件都在根目录下。'
2. /bin: 存放基本命令的二进制文件的目录，其主要存放Linux下常用的命令和工具。
3. /boot: 该目录存放了启动Linux时所需的核心文件，包括连接文件、内核文件等。
4. /dev: Linux中访问设备的方式和访问文件的方式时相同的。外围设备（磁盘、打印机、终端等）都以文件形式存放在于此目录中。
5. '/etc': '存放系统的配置文件，例如：账号密码文件、各种服务的启停文件等。一般情况下，配置文件只能通过root用户修改，例如：网卡配置文件、SSH服务配置修改等。'
6. '/home': 该目录下存放普通用户的家目录(home directory)，当新增一个普通账号时，该目录下就会创建一个文件夹用于保存该账号个人数据和配置文件。
7. /lib: 该目录下存放开机时用到的函数库，以及在/bin或/sbin下的指令会调用的函数库。函数库又名动态链接共享库，作用类似Windows里的DLL文件。
8. /mnt: 存放系统文件的临时挂载点的目录，主要用于挂载外围设备。
9. /opt: 该目录主要用于安装第三方软件，且其安装后的数据、库文件等都存放在该目录下。只要将该目录下特定软件文件夹删除则该软件就直接卸载。
10. /root: 系统管理员(root)的家目录。
11. 'tmp': 存放临时文件，一般使用者或正在执行的程序可将文档放置于此。该目录是任何人都能存取的，所以需要定期清理。需要注意的是，重要资料不可放置在此目录。
12. /usr: 存放次重要的分级文件系统的目录，它通常用来安装各种软件。
13. '/var': 该目录用于存放系统中经常发生变化的数据，例如：系统日志文件、邮件以及应用程序的数据文件等。
14. '/var/log': '存放日志文件的目录'。

5. max: 密码有效期天数，99999代表永不过期
6. warn: 密码过期前多少天开始向用户发送警告
7. inactive: 密码过期后账号仍可登录的宽限天数
8. expire: 账号失效的具体日期(Unix时间戳)，到期锁定
9. flag: 保留域，暂未使用
# 核心安全优势与管理特征
1. 权限隔离与加密存储: 将密码从公开可读的/etc/passwd迁移至仅root可读的/etc/shadow，密码采用MD5不可逆算法加密，彻底杜绝非授权用户的密码窥探风险，root仅可执行重置或禁用操作。
2. 全生命周期管控：自动记录密码最后修改时间，支持设置密码有效期(Max)和最小使用周期(Min)，即防止密码长期不换，也避免用户频繁变更密码导致记忆混乱。
3. 全局策略标志化: 通过/etc/login.defs配置系统密码策略，如密码最小长度、密码过期前告警天数、账号非活跃期锁定等，建立统一的账号安全基线。
4. 管理规范化: 强制使用专用命令(useradd/passswd/usermod)进行账号管理，直接修改/etc/passwd将失效，规避了手动编辑系统文件可能带来的配置错误与安全隐患。

Linux日志管理

### 日志文件的分类
# 连接时间日志
由多个程序执行，把记录写入到/var/log/wtmp和/var/run/utmp，通过login等程序更新wtmp和utmp文件，使系统管理员能够跟踪谁在何时登录到系统。
# 进程统计日志
由系统内核执行。当一个进程终止时，为每个进程往进程文件(pacct或acct)中写入一个记录。进程统计的目的是为系统中的基本服务提供命令统计。
# 错误日志
各种系统守护进程、用户程序和内核通过syslogd守护程序向文件/var/log/messages报告值得注意的事件。另外，有许多UNIX程序创建日志，HTTP和FTP等提供网络服务的服务器也保持详细的日志。
# 应用程序日志
许多程序通过维护日志来反馈系统的安全状态。su命令允许用户获得另一个用户的权限，所以它的安全很重要，它的文件为sulog，同样的还有sudolog。另外，诸如Apache等HTTP的服务器都有两个日志: access_log(客户端访问日志)以及error_log(服务出错日志)。FTP服务的日志记录在xferlog文件中，Linux下邮件传送服务(sendmail)的日志一般存放在maillog文件当中。

### 常用日志文件
默认位于 /var/log目录下
1. access-log # 记录HTTP/Web的传输
2. acct/pacct # 记录用户命令
3. boot.log # 记录Linux系统开机自检过程显示的信息
4. lastlog # 记录最近几次成功登录的事件和最后一次不成功的登录
5. messages # 从syslog中记录信息(有的连接到syslog文件)
6. sulog # 记录使用su命令的使用
7. syslog # 从syslog中记录信息
8. utmp # 记录当前登录的每个用户信息
9. wtmp # 一个用户每次登录进入和退出事件的永久记录
10. xferlog # 记录FTP会话信息
11. maillog # 记录每一个发送到系统或从系统发出的电子邮件的活动，它可以用来查看用户使用哪个系统发送工具或把数据发送到哪个系统。	
# 日志消息的级别（从高到低）
0. EMERG(紧急): 系统不可用的严重故障，如内核崩溃、硬件故障等，需立即处理。
1. ALERT(警告): 必须立即采取行动的问题，如数据库损坏、关键服务停止。
2. CRIT(严重): 严重的系统错误，如磁盘空间耗尽、关键服务停止。
3. ERR(错误): 常规运行错误，如服务启动失败、文件读写异常，需排查修复。
4. WARNING(提醒): 潜在风险提示，如配置文件过期、资源使用率偏高，需要关注。
5. NOTICE(注意): 正常但值得记录的事件，如用户登录、服务重启，用于审计追踪。
6. INFO(信息): 普通允许信息，如服务启动成功、系统状态正常，用于日常监控。
7. DEBUG(调试): 程序调试与开发日志，包含详细的变量、调用栈信息，用于问题排查。
# 日志记录的一般格式
1. 时间标签: 精确记录日志产生的日期与具体时分秒，是排查系统时间时间线、定位故障发送时刻的核心依据。
2. 主机名: 标识生成该日志消息的服务器名称，在多服务器集群环境中，可快速区分日志来源的具体节点。
3. 子系统名: 指定消息的来源主体，如内核(kernel)、系统服务(sshd/NetworkManager)或用户进程，用于定位问题所属的系统模块。
4. 消息字段: 日志的核心内容，包含事件描述、错误代码、状态变化、操作结果等关键信息，是分析故障原因的直接依据。
# 示例
1. wtmp和utmp为二进制文件，不能用文本查；命令直接查看，可以通过who、w、users、last和ac查看这两个文件包含的信息。
2. who命令查询utmp文件输入包含用户名、终端类型、登录日期及登录的来源主机
3. who命令跟wtmp文件名，则可以查看所有的登录记录信息。
4. 'w命令': 查询utmp文件，展示当前系统所有登录用户及进程信息，包括登录名、终端、远程主机、登录时长、空闲时间、进程占用CPU等关键数据。
5. 'users命令': 以单元形式输出当前所有登录的用户名，每个用户名对应一个独立的登录会话，简洁展示系统当前的用户概况。
6. 'last命令': 回溯读取wtmp日志文件，呈现从文件创建至今的所有用户登录历史记录，包括登录时间、来源地址、登出时间等信息。

Netfilter/Iptables防火墙原理与配置

### 一、Linux包过滤防火墙概述
# Netfilter 内核态
1. 集成在Linux内核中的包过滤功能体系，是防火墙的核心实现层。
2. 工作在系统内核空间，负责对进出服务器的数据包进行实际的过滤、转发、修改等操作。
# iptables 用户态
1. 位于/sbin/iptables路径下的命令行工具，属于防火墙的规则管理接口
2. 通过iptables命令可以向内核态Netfillter添加、删除、修改防火墙规则，实现对网络访问的管控。


### 二、Linux包过滤防火墙工作层次
# 包过滤的工作层次
1. 主要是网络层，解析IP包头信息，包括源/目的IP、协议类型、端口号等
2. 体现在对包内的IP地址、端口等信息的处理上


### 三、etfilter/Iptables架构
Netfilter是Linux内核的底层数据包处理引擎，通过[表(Tables) -> 链(Chains) -> 规则(Rules)] 的三层层级结构实现对网络数据包的过滤、修改与转发控制。表是功能分类容器，链式规则的执行队列，规则是具体的匹配条件与动作指令。
## (一) iptables内置了4个表，即filter表、nat表、mangle表和raw表。【四表】
1. raw表: 确定是否对该数据进行状态跟踪 (使用率不高)
2. mangle表: 为数据包设置标记
3. nat表: 修改数据包中的源、目的IP或端口
4. filter表: 确定是否放行该数据包(过滤)
# Filter表(默认表) -- 防火墙核心
负责数据包的过滤决策，决定数据包的 [放行ACCEPT、丢弃DROP 或 拒绝REJECT]，是构建主机防火墙的核心表，包含 [入站INPUT、出战OUTPUT、转发FORWARD] 三大核心链。
# NAT表 -- 地址与端口转换
实现网络地址转换功能，包含 SNAT(源地址转换，内网访问外网)、DNAT(目的地址转换，端口映射)、MASQUERADE(动态源转换)，是网关与代理服务器的核心配置表。
# Mangle表 -- 数据包整形与标记
用于修改数据包的IP头部信息(如TTL生存期、TOS服务类型)，或为数据包添加内核标记(Mark)，支持策略路由、流量整形等高级网络管控场景
# Raw表 -- 绕过连接跟踪的高性能表
优先级最高的表，用于再连接跟踪(Conntrack)之前处理数据包，可配置绕过连接跟踪机制，提升高并发网络场景下的处理性能，也用于解决特殊无状态数据包的处理问题。

## (二) 链(Chains)的本质: 数据包的 “检测清单” 【五链】
链是数据包在系统中流转的路径与规则集合。当数据包到达某条链时，系统会逐条匹配规则: 满足条件则执行对应动作(如放行、丢弃)；若无一匹配，则执行链的默认策略。
# 系统默认的五大核心规则链
1. INPUT链: 专门处理目标地址为本机的入站数据包，是主机防护的第一道关卡。
2. OUTPUT链: 处理由本机主动发起的出战数据包，控制主机对外的网络访问请求。
3. FORWARD链: 针对经过本机转发的数据包生效，是路由器、网关设备的核心过滤规则链。
4. PREROUTING链: 数据包到达网络层后、路由决策前触发，常用于DNAT(目的地址转换)配置。
5. POSTROUTING链: 路由决策完成后、数据包离开本机前触发，常用于SNAT(源地址转换)与MASQUERADE(地址伪装)

## (三) 规则(rules)
规则是网络管理员预定义的匹配条件与动作组合，核心逻辑为“若数据包满足条件，则执行对应动作”。规则存储于内核空间的过滤表中，匹配维度包含源/目的IP、传输协议(TCP/UDP/ICMP)及服务端口(HTTP/FTP等)。匹配成功后，执行动作包括：放行(Accept)、拒绝(Reject，返回错误包)、丢弃(Drop，无响应)。防火墙的配置本质就是对规则的增删改查与策略优化。如规则表执行顺序图所示。


### 四、Netfilter/Iptables架构
## (一) raw表
ip_conntrack (nf_conntrack) 连接追踪
- 内核维护一张 '会话记录表'，记录TCP/UDP会话(源/目的IP、端口、连接状态)
- 用途: ①支持'-m state'状态防火墙; ②NAT 地址转换必须依赖此表
- 代价: 消耗内存CPU；高并发场景表满会导致丢包
# raw表特点(优先级最高)
- 仅2条链: REROUTING、OUTPUT
- 唯一核心动作: NOTRACK (不做连接追踪)
- NOTRACK != 丢弃数据包，报文仍然经过 filter 表做过滤
# NOTRACK 效果
1. 数据包不在写入conntrack会话表，节约系统资源;
2. 自动跳过后续NAT规则 (NAT依赖连接追踪)
3. 不能再使用state状态模块匹配流量
# 示例
iptables -t raw -A PRROUTING -d 192.168.56.102 -j NOTRACK

## (二) mangle表
mangle表核心价值: 在路由决策之前(PRROUTING链)修改数据包标记，实现流量的精细化路径控制。
实现逻辑: 通过MARK标记为流量分类，集合Linux多路由表机制，让不同业务流量走不通的出口网关，满足带宽管理或安全隔离需求。
# STEP1: 为不同的业务流量打标记(MARK)
为Web服务 (80/443端口) 打上标记1；为FTP服务(20/21端口)打上标记2
iptables -t mangle -A PRROUTING -i eth0 -p tcp --dport 80:443 -j MARK --set-mark 1
iptables -t mangle -A PRROUTING -i eth0 -p tpc --dropt 20:21 -j MARK --set-mark 2
# STEP2: 配置策略路由表与规则绑定
定义两个独立的路由表 (10和20)，指向不通的出口网关
ip route add default via 202.106.xx.xx dev eth1 table 10 # 标记1流量走此路由
ip route add default via 211.108.xx.xx dev eth2 table 20 # 标记2流量走此路由
ip rule add from all fwmark 1 table 10 # 绑定标记与表
ip rule add from all fwmark 2 table 20 # 绑定标记与表

## (三) nat表
- NAT 是将局域网的内部地址转换为公网上的IP地址，从而使得内部主机能像公网的主机一样上网。NAT将自动修改IP报文中的源IP和目的IP地址，IP地址校验在NAT处理过程中自动完成。网络地址转换分为'源地址转换与目的地址转换'两种。
- SNAT(源地址转换) 数据包出网卡时替换源IP为公网IP，使对端认为来自公网主机，从而正常响应，是内部访问外网的关键技术。
# 示例1-SNAT: 
公司内网主机(192.168.1.100)访问公网时，网关通过SNAT将源IP转换为服务器公网IP(218.29.30.21)，实现对外通信。
- 实现关键: SNAT需要在路由决策后指向，因此必须配置在POSTROUTING链上，属于nat表的核心规则。
- 配置实例: 使用iptables命令将内网192.168.1.0/24网段的源IP转换为公网IP 218.29.30.21, 实现共享上网
iptables -t nat -A POSTROUTING -s 192.168.1.100 -o ens33 -j SNAT --to-source 218.29.30.31 # iptables -L -t nat 查看
# 示例2-DNAT:
外部用户访问公司公网IP (如218.29.30.31)的Web服务，通过DNAT转发至内网服务器(如192.168.1.6)
- 使用Linux系统中的iptables可实现DNAT功能。DNAT是在数据报文进行路由选择前进行的，因此其使用在PREROUTING链上。
- 配置iptables使得从本机网卡流入的数据包从目的IP是218.29.30.31替换为目的IP是192.168.1.6.
iptables -t nat -A PREROUTING -i ens33 -d 218.29.31.31 -p tcp --dport 80 -j DNAT --to-detination 192.168.1.6



### 五 iptables基本语法
iptables -t filter -I INPUT -p icmp -j DROP # -I 在INPUT的开头插入规则
iptables -t filter -I INPUT 3 -p icmp -j DROP # -I 在INPUT的3序号插入规则
iptables -t filter -A INPUT -p icmp -j DRO # -A是在INPUT的末尾追加规则
iptables [-t 表名] 选项 [链名] [条件] [-j 控制类型]
# 几个主要事项
- 不指定表名时，默认指filter表
- 不指定链名时，默认指表内的所有链
- 除非设置链的默认策略，否则必须指定匹配条件
- 选项(I/A)、链名、控制类型使用大写字母，其他均为小写
- 选项，添加新的规则: -A是末尾追加，-I是链的开头(或指定序号)插入一条规则
## (0) 数据包的常见控制类型:
iptables [-t 表名] 选项 [链名] [条件] [-j '控制类型']
- ACCEPT: 允许通过
- DROP: 直接丢失，不给出任何回应
- REJECT: 拒绝通过，必要时给出提示
- LOG: 记录日志信息，然后传给下一条规则继续匹配
- MASQUERADE: 是SNAT的一种特殊形式，适用于动态的地址分配
- SNAT: 源地址转换
- DNAT: 目的地址转换

## (1) iptables的管理选项 A/I, D/F, L, P 
iptables [-t 表名] '选项' [链名] [条件] [-j 控制类型]
# 新增规则 要大写
-A: 在链的末尾追加一条规则
	iptables -t filter -A INPUT -p icmp -j DRO # -A是在INPUT的末尾追加规则
-I: 在链的开头 (或指定序号) 插入一条规则
	iptables -t filter -I INPUT -p icmp -j DROP # -I 在INPUT的开头插入规则
	iptables -t filter -I INPUT 3 -p icmp -j DROP # -I 在INPUT的3序号插入规则
# 查看规则列表
-L: 列出所有的规则条目
-n: 以数字形式显示地址、端口等信息
-v: 以更详细的方式显示规则信息
--line-numbers: 查看规则时，显示规则的序号
iptables -t filter -L INPUT -n -v --line-number # 查看 filter 表某条链，并显示规则编号
# 删除、清空规则
-D: 删除链内指定序号(或内容)的一条规则
-F: 清空所有的规则
iptables -D INPUT 3   # 删除 INPUT 链里编号为 3 的那条规则
iptables -F INPUT        # 清空 INPUT 链所有规则
iptables -F              # 清空 filter 表所有链（危险，慎用）
iptables -t nat -F
iptables -t mangle -F
iptables -t raw -F
# 设置默认策略
-P: 为指定的链设置默认规则。（只有ACCEPT，和DROP，没有REJECT）
1. '黑名单安全策略(宽松)': 默认策略为ACCEPT，链中的规则对应的动作应该为DROP或者REJECT，表示只有匹配到规则的报文才会被拒绝，没有被规则匹配到的报文都会默认接收。
iptables -P OUTPUT ACCEPT
2. '白名单安全策略(严格)': 链的默认策略为DROP，链中的规则对应的动作应改为ACCEPT，表示只有匹配到规则的报文才会被放行，没有被规则匹配到的报文都会被默认拒绝。
iptables -t filter -P FORWARD DROP
# 其他
service iptables save # 删完一定要保存，否则重启就回来


## (2) iptables规则匹配条件
iptables [-t 表名] 选项 [链名] ['条件'] [-j 控制类型]
# 常见的通用匹配条件 '!'表示条件取反
1. 协议匹配: -p 协议名
	iptables -I input -p icmp -j DROP
	iptables -A FORWARD -p ! icmp -j ACCEPT
2. 地址匹配: -s 源地址, -d 目的地址
	iptables -A FORWARD -s 192.168.1.11 -j REJECT
	iptables -I INPUT -s 10.20.30.0/24 -j DROP
3. 接口匹配: -i 入职网卡, -o 出站网卡
	iptables -A INPUT -i eth1 -s 192.168.0.0/16 -j DROP
	iptables -A INPUT -i eth1 -s 10.0.0.0/8 -j DROP
	iptables -A INPUT -i eth1 -s 172.16.0.0/16 -j DROP
4. 端口匹配: --sport源端口, --dport目的端口
	iptables -A FORWARD -s 192.168.4.0/24 -p udp --dport 53 -j ACCEPT
	iptables -A INPUT -p tcp --dport 20:21 -j ACCEPT

TCP_Wrappers访问控制机制

### TCP_Wrappers基础
1. TCP_Wrappers是Linux/Unix系统中轻量级的安全访问控制工具，作为“服务请求”与“系统服务”的中间校验层，通过配置文件 (hosts.allow/deny) 实现服务级的黑白名单管控，同时记录所有连接日志，常与inetd/xinetd守护进程配合，覆盖SSH、FTP、HTTP、SMTP等主流网络服务。
2. 当inetd接收到外部服务请求时，并非直接调用服务进程，而是先转交TCP_Wrappers; TCP_Wrappers依据预设的访问规则 (允许/拒绝) 校验请求源的合法性; 校验通过则将请求转发给对应服务守护进程，同时记录连接日志；若校验失败则直接阻断请求，从源头拦截非法访问。

### iptables 和 TCP_Wrappers的区别
1. iptables时防火墙软件，归于第4层传输层，作用于第3层和第4层，对IP、Port、传输层协议(tcp、udp)进行限定。
2. TCP_Wrappers是安全工具，归于第7层应用层，作用于第3层和第7层，对IP、应用层协议(ssh、http、ftp等)进行限定。
3. 执行顺序: iptables -> TCP_Wrappers -> 本地服务。
4. Linux 本身有两层安全防火墙。第一层防护 (iptables): 拦截网络层恶意流量，阻挡非法IP/Port的访问; 第二层防护(TCP_Wrappers):对通过第一层的请求进行应用服务级准入校验; 最终合法请求抵达本地服务进程。双层防护实现了 “从网络流量到应用服务” 的纵深防御体系。


### TCP_Wrappers工作原理
以SSH为例，每当SSH的连接请求时，先读取系统管理员所设置的访问控制文件，符合要求，则会把这次连接原封不动的转给ssh进程，由ssh完成后续工作，如果这次连接发起的IP不符合访问控制文件中的设置，则会中断连接请求。拒绝SSH访问。
# 通过两个配置文件来控制:
1. /etc/hosts.allow # 定义允许的访问
2. /etc/hosts.deny # 定义拒绝的访问
- 优先查看 hosts.allow 文件，匹配访问控制策略
- 允许个别拒绝所有: hosts.allow文件添加单个允许的策略，hosts.deny文件添加 all
- 拒绝个别允许所有: hosts.deny文件添加单个拒绝的策略，hosts.allow文件为空


### TCP_Wrappers配置文件格式
daemon_list: client_list [[[:option] :option] ...]
## deamon_list: 守护进程
必须填写 /usr/sbin 目录下的应用程序文件名，支持多种匹配方式:
1. 单服务名: 直接写程序名, 如 vsftpd、 sshd
2. 多服务列表: 逗号分隔, 如 sshd,vsftpd
3. 通配符: ALL 代表所有受 TCP_Wrappers 管控的服务
## client_list: 客户端
支持IP地址、主机名或网段匹配，网段需要注意掩码格式规范:
1. 基础匹配: 单个IP (如192.168.1.10) 或可解析的主机名
2. 标准网段: 需要使用完整子网掩码，如 172.16.0.0/255.255.0.0
3. 简洁网段: 省略后端，如172.16. 匹配172.16开头的所有地址。
## :option 控制选项
1. deny: 拒绝, 主要用于hosts.allow文件，定义拒绝访问规则
2. allow: 允许, 主要用于hosts.deny文件，定义允许规则
3. spawn: 触发外部脚本 (如日志记录、邮件告警) 来执行后续的命令，增强审计能力

#### Snort (NIDS)
# Snort核心概述
Snort是一款轻量级、开源免费的网络入侵检测系统 (NIDS)，遵循GPL协议，使用于大中小型网络环境，尤其适合无法承担商业IDS高昂成本的中小企业，是网络安全防御体系中的重要工具。
# 核心功能特性
1. 轻量高效: 代码简洁短小，资源占用低，可在普通硬件上流畅运行，不影响网络性能。
2. 实时检测: 具备实时流量分析与工具检测能力，支持TCP/UDP/ICMP等主流协议解析，快速发现并告警各类网络攻击行为。
3. 跨平台兼容: 完美支持Linux、Solaris、BSD、HP-UX即Windows等主流操作系统，部署灵活。
4. 灵活扩展: 支持插件机制，可通过插件扩展功能，同时利用FlexResp模块实现主动阻断恶意连接，提升防御能力。
# 三种核心工作模式 （常考）
Snort具备三种核心工作模式: '嗅探器模式'(实时抓取并显示网络数据包流)、'包过滤模式'(将捕获的流量持久化存储至硬盘)、'网络入侵检测模式'(NIDS，基于规则库分析流量，识别攻击行为并触发告警/阻断动作)。其中NIDS模式支持灵活的规则配置，是实现入侵检测的核心。

### 一、作为嗅探器模式的参数应用

# 参数和功能说明
1. -v: 基础模式: 仅显示数据包的 TCP/IP 层包头信息
2. -vd: 详细模式: 展示IP、TCP、UDP、ICMP等协议的详细包头字段
3. -vde: 完整模式: 同时输出 '包头信息' 与数据包的 '实际载荷' (数据内容)
4. -c: 配置加载: 指定Snort运行时使用的规则配置文件 (如 snort.conf)

### 二、作为包过滤器模式
Snort可将截获的网络数据包完整记录至指定日志文件，是入侵检测与流量审计的基础功能。通过配置不同参数，可灵活定义日志的存储路径、格式及输出方式，满足不通常见下的审计与分析需求。
more snort.log.1234324123 # 查看日志
# 关键参数和功能说明
1. -l <log_dir>: 指定日志文件的存放目录，需确保目录已存在且有写入权限。
2. -h <IP/Host>: 定义受保护的主机网络(Home Network)，用于区分内外网的流量。
3. -b: 以二进制格式 (tcpdump格式)记录数据包，节省空间且便于后续分析。
4. -s: 将日志信息发送给系统syslog服务，便于日志的集中收集与管理。

### 三、作为网络入侵检测
./snort -vde -l /var/log/snort -c /etc/snort/snort.conf # 启动入侵检测共功能: 完整模式，输出目录，配置文件
snort最重要的用途还是作为网络入侵检测系统。能够实时监控网络流量，通过预定义的规则库识别攻击行为并触发告警。它通过分析数据包的特征，有效防御端口扫描、DDOS攻击、缓冲区溢出等多种威胁，是构建网络安全防线的重要工具。
# 帮助snort实现网络入侵检测功能的参数如下表所示。
1. -c <file>: 指定Snort配置文件路径，包含检测规则库
2. -A <mode>: 配置告警输出模式 (如full/quick/console)
3. -b: 以二进制格式快速记录原始网络数据包
4. -s: 将告警信息转发至系统syslog日志服务
5. -M WORKSTATIONS: 使用SMB警报机制 (Windows的弹窗告警)。
# 警报机制
snort的警报机制有full, fast, socket, none, smb(winpopup)和syslog等6种。其中，前4种警报机制可以使用-A参数设置，如下
1. -A fast: 输出精简的报警信息，仅包含关键要素: 时间戳、报警分类信息、源IP/目的IP地址及通信端口，适合快速查看与日志归档。
2. -A full: 完整报警模式，输出包含数据包的详细信息(如协议细节、负责内容片段)，适合深度审计与入侵行为分析。
3. -A unsock: 将报警信息通过UNIX本地套接字发送给第三方进程，支持实时联动处理(如联动防护墙阻断、自动化响应脚本)
4. -A none: 完全关闭报警输出功能，仅进行数据包检测而不生产任何报警日志，适用于仅需流量分析或性能优先的场景。
使用建议: 日常监控推荐使用 -A fast以节省日志存储空间；若需取证分析或深度排查，则使用-A full; 若需与自动化运维平台联动, -A unsock是最佳选择。

### 四、Snort规则 （考试内容）
snort作为网络入侵检测系统，拥有自己的规则语言。从语法上看，该规则语言非常简单，又足够强大。
# snort规则语法
1. 规则由两部分组成: '规则头部'定义流量的基本五元组特征(动作、协议、源/目的IP、源/目的端口)；'规则选项'则包含报警信息、工具特征码(如内容匹配、正则表达式)等关键检测条件，是判定是否触发规则的核心依据。
2. 标准格式: 'rules_action protocol src_ip src_port -> dst_ip dst_port' (rules_option)
3. 其中rules_action为规则动作(如alert报警、log记录、pass放行)、protocol(网络协议，如tcp/udp/icmp)、箭头左侧为源端信息，右侧为目的端信息。例如
log tcp any any -> 192.168.0.0/24 21
使用这条规则，snort可以将任意网络到网络192.168.0.0/24的21端口的数据报记录到日志中，用于审计FTP访问行为。

## (1) Snort规则头
# rules_action(规则动作): 
alert报警(如弹窗、邮件，写入日志), log记录(写日志), pass放行(不记录，用于白名单流量)
# protocol(网络协议): 如tcp/udp/icmp等
# 通信方向
1. ->: 箭头左侧为源端信息，右侧为目的端信息。
2. <>: 定义双向通信，明确流量流向边界。
# 地址与端口: 支持 “网络/掩码” 格式(如192.168.0.0/24); 'any'匹配任意IP/端口, '!'表示取反, ':'指定端口范围(1024:65535)
# 实例1: log tcp any any -> 192.168.0.0/24 21
解析: 使用这条规律，snort可以将任意网络到网络192.168.0.0/24的21端口的数据包记录到日志中，用于审计FTP访问行为。
# 实例2: alert tcp ! 192.168.0.0/24 any -> 192.168.0.0/24 1024:65535 (msg: "tcp traffice";)
解析: 监控内网192.168.0.0/24网段，对从非192.168.0.0/24网络的任意端口发往该网段1024-65535端口的TCP流量进行告警。

## (2) Snort规则选项(默认规则目录/etc/snort/rules)
规则选项是Snort入侵检测引擎的核心逻辑载体，封装在规则的括号内，各选项以分号";"分隔。它们定义了检测的具体条件、匹配深度、响应动作及日志信息，是实现精确威胁检测的关键要素，灵活组合可应对多样化的网络工具场景。
# Snort支持如下所示的选项。
1. content: 用于匹配数据包应用层的负载内容，是检测攻击特征（如恶意指令、病毒特征码）的核心选项。
2. msg: 定义触发规则时输出的报警或日志信息，帮助管理员快速识别告警事件的类型与描述。
3. flags: 检查TCP头部的标志位(如SYN、ACK、FIN、RST等)，用于识别特定的TCP连接状态或扫描行为。
4. depth: 指定内容匹配时在数据包负责中搜索的最大深度，合理设置可减少误报并提升检测效率。
5. ack: 检查TCP头部的确认号(Acknowledgment Number)字段，用于匹配特定的TCP会话确认状态。
# 实例1 new_rule.rules
alert tcp ! 192.168.0.0/24 any -> 192.168.0.0/24 80 (msg:"Web traffic"; sid:1000001; rev:1;)
解析: 该规则表示警报从外网的任意端口到192.168.0.0/24的所有Web通信，同时定义了规则ID(sid)和版本号(rev)
生效方法: 在/etc/snort/snort.conf文件末尾添加: include $RULE_PATH/new_rule.rules, 重启服务systemctl restart snort
# 示例2 详细示例
alert http any any -> $HOME_NET any (msg:"Potential SQL injection attempt"; content:"SELECT|2b|OR|2b|INSERT|2b|UPDATE|2b|DELETE"; nocase; threshold:type both; track by_src, count 3, seconds 10; sid:1000005; rev:1;)
# 示例2 解析
- alert表示触发这个规则时产生一个警报。http指定协议为HTTP。any any 表示源IP地址和源端口可以是任意的。->表示数据包的流向。$HOME_NET any表示目的为内网网络（通过变量定义）的任意端口。
- (msg: "Potential SQL injection attempt";: 设置警报消息为"Potential SQL injection attempt"，即潜在的SQL注入尝试。
- content:"SELECT|2b|OR|2b|INSERT|2b|UPDATE|2b|DELETE";nocase;: 检查HTTP数据包中是否包含常见的SQL关键字，如"SELECT、OR、INSERT、UPDATE、DELETE"等，这里的"2b"表示空格的十六进制表示，nocase表示不区分大小写，因为SQL注入尝试可能以各种大小写形式出现。
- threshold用于设置触发警报的阈值条件。type both表示同时对警报数量和时间进行监测。track by_src表示根据源IP地址进行跟踪count 3表示在10秒内如果来自同一个源IP的满足该规则的数据包数量达到3个，则触发警报。seconds 10表示时间窗口为10秒。
- sid是规则的唯一标识符，这里为1000005。rev是规则的版本号，这里为1.
- 这个规则可以检测到可能的HTTP请求中的SQL注入尝试行为，当在特定时间内来自同一源IP的多个请求中包含可疑的SQL关键字时，Snort会发出警报，提醒管理员防范潜在的SQL注入攻击。
